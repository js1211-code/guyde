## 프로젝트 개요
- 제품: BASE(베이스) — 자기관리 질문을 올리면 대중이 검증한 "무난함"을 돌려받는 남성 자기관리 커뮤니티 웹앱.
- 태그라인: 일단, 베이스부터.
- 포지션: 안티-동경. "멋져져"가 아니라 "안 망해". 판단자는 전문가가 아니라 대중.
- 맥락: 해커톤 데모. 솔로 개발.
- 핵심 지표(NSM): 답변 받은 글 비율(= 커뮤니티 유동성).

## 기술 스택 (고정 — 함부로 바꾸지 말 것)
- Next.js 16 (App Router) + TypeScript
- Tailwind CSS + shadcn/ui
- Supabase (PostgreSQL, Storage) — **Auth는 쓰지 않는다**
- 서버 로직: Next.js Route Handlers (`app/api/...`)
- 클라이언트 상태/패칭: TanStack Query
- 배포: Vercel + Supabase Cloud
- ❌ 결제 PG 연동 없음 (안내 문구만)

## 실행 명령
- 개발 서버: `npm run dev` (http://localhost:3000)
- 빌드: `npm run build` / 린트: `npm run lint`

## 🔑 인증 — 로그인 없음 (가장 중요한 구조)
- 앱 최초 진입 시 클라이언트가 **UUID v4를 생성해 localStorage에 저장**. 온보딩·로그인·회원가입 화면 **없음** — 진입 즉시 피드.
- 서버는 `users.device_id`로 신규/기존을 판별하고, 신규면 **랜덤 닉네임**을 발급한다.
- 랜덤 닉네임: `[형용사] [동물] #[4자리]` (예: 부지런한 판다 #3901). 단어 풀 각 20개 이상, **긍정·중립 어휘만**(외모·능력 비하 금지 — 안전지대가 컨셉의 핵심). 조합 중복 시 숫자만 재발급.
- 모든 API 요청에 **`X-Device-Id: <UUID>` 헤더**를 실어 보낸다. 서버는 이 헤더만으로 작성자·투표자를 판별.
- **세션·JWT·쿠키를 쓰지 않는다. 세션/토큰 테이블·비밀번호 컬럼을 만들지 않는다.**
- ❌ Supabase Auth, `auth.uid()`, 소셜 로그인 전부 사용 금지.

## 보안 규칙 (v1과 완전히 다름)
- 기기 UUID는 Supabase가 검증할 수 없다 → **RLS 정책을 만들지 않고 전 테이블 차단**(anon/authenticated는 0행).
- **모든 데이터 접근은 서버 Route Handler를 경유한다.** 클라이언트에서 `supabase.from(...)` 직접 호출 금지.
- 서버는 `SUPABASE_SECRET_KEY`로 접근하고, 요청의 `X-Device-Id` 헤더를 검증한다. 헤더 없는 요청은 거부.
- 환경변수(.env.local):
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `SUPABASE_SECRET_KEY` (서버 전용, `NEXT_PUBLIC_` 접두사 절대 금지)

## 데이터베이스 (v2.0 — 17 테이블 + 뷰 1)
전체 DDL은 Notion "기술 스택" 페이지 / `db/schema_v2.sql`. 요약:
- **users** — `device_id`(PK), nickname(unique), temperature(36.5), hearts(>=0)
- **posts** — device_id, category, post_type, title, body
- **post_images** — 사진 여러 장(url, sort_order)
- **poll_options / poll_votes** — 선택지 투표(2~5개). PK(post_id, device_id) = 1기기 1표
- **nanhan_votes** — 무난함 판정('무난해요'|'애매해요' 고정 2종). PK(post_id, device_id)
- **comments / comment_likes** — 1단계 댓글(대댓글 없음). likes는 트리거 자동 관리, 자기 댓글 추천 차단
- **articles / quizzes / quiz_results** — 매거진 아티클·테스트
- **experts / reviews / expert_slots / bookings** — 컨설팅(시드 고정)
- **heart_transactions** — 하트 원장
- **reports** — 신고(버튼 자리만)
- 뷰: **posts_feed** — 피드 카드에 필요한 집계(썸네일·댓글수·투표수·무난함%)를 한 번에

### ★ 절대 헷갈리면 안 되는 두 축
- `category` = **주제**: `옷` | `스킨케어` | `바디&향수` | `자유`
- `post_type` = **물어보는 방식**: `일반글` | `선택지투표` | `무난함판정`
- **"무난무난"은 카테고리가 아니라 `post_type='무난함판정'` 필터다.** category enum에 절대 넣지 말 것(DB CHECK로도 막혀 있음).

## 데이터 접근 규칙 (앱 코드가 반드시 지킬 것)
1. 피드 조회는 **`posts_feed` 뷰**로. 무난함 %는 이 뷰에서만 계산한다 — 피드 배지와 상세가 같은 값을 써야 함.
2. 글 작성은 **`create_post(device, category, type, title, body)` 함수**로 (하트 차감 + insert가 한 트랜잭션). 하트 부족 시 `INSUFFICIENT_HEARTS` 예외.
3. 투표는 **`cast_poll_vote()` / `cast_nanhan_vote()` 함수**로 (upsert — 다른 선택지 누르면 표가 이동).
4. `comments.likes` 직접 update 금지 — `comment_likes` 삽입/삭제 시 트리거가 자동 반영.
5. 무난함 % = 무난해요 ÷ (무난해요 + 애매해요) × 100. **0표면 null → 배지 숨김.**
6. 내 글·내 댓글·내 예약 조회는 전부 `device_id` 기준.

## 핵심 도메인 규칙
- **정체성 대칭**: 글도 댓글도 **같은 닉네임 + 온도**로 표시한다. "익명 vs 실명" 비대칭을 만들지 않는다(v1 설계 폐기).
- 닉네임을 변경해도 device_id는 그대로 → 과거 글·댓글·온도가 모두 따라온다.
- **투표 전에는 결과를 보여주지 않는다.** 선택지 투표글은 투표해야 득표율·%가 공개된다.
- 무난함 판정글은 작성자가 선택지를 만들 수 없다 — '무난해요/애매해요' 고정 2종.
- 온도: 36.5 시작. `자유` 카테고리는 온도 미적립(잡담방). **산식·고수 기준치 미확정** → UI만 만들고 값은 임시.
- 고수는 시드 고정(유저가 고수가 되는 경로는 만들지 않음). 고수도 랜덤 닉네임 체계를 쓴다.
- 하트: 배지 표시 + 글 작성 시 1개 차감까지만. 충전·구매 없음. **시간 부족하면 가장 먼저 자를 항목.**

## 화면 구조
- 하단 4탭: **커뮤니티 / 매거진 / 컨설팅 / 내정보** + 글쓰기 **FAB**(우하단, 커뮤니티 탭에서만 노출)
- 피드 탭 6개(가로 스크롤): `전체 | 무난무난 | 옷 | 스킨케어 | 바디&향수 | 자유`
- 글쓰기: 카테고리 필수 + **물어보는 방식 3택 필수**(선택 시 해당 템플릿 로드) → 투표면 선택지 입력 2~5개, 무난함이면 고정 버튼 안내
- 라우트: `/`(피드) · `/post/[id]` · `/write` · `/magazine` · `/magazine/[id]` · `/magazine/quiz/[slug]` · `/experts` · `/experts/[id]` · `/booking/[expertId]` · `/booking/done/[id]` · `/me` · `/me/activity` · `/me/bookings`

## 코딩 컨벤션
- 모든 코드 TypeScript. `any` 지양.
- App Router: 서버 컴포넌트 기본, 상호작용 필요할 때만 `"use client"`.
- 폴더: 라우트 `app/`, API `app/api/`, 공용 로직 `lib/`, 컴포넌트 `components/`, DB SQL `db/`.
- 네이밍: 파일 kebab-case, 컴포넌트 PascalCase, 변수/함수 camelCase, DB 컬럼 snake_case.
- 작은 단위로 자주 커밋. 새 라이브러리는 꼭 필요할 때만 추가하고 이 문서에 기록.

## 기능 우선순위 (이 순서로 구현)
1. **공통 기반** — 기기 UUID 발급·유저 등록·랜덤 닉네임·X-Device-Id 헤더·4탭+FAB
2. **커뮤니티 핵심** — 피드(탭 6개·정렬·카드 3종) → 글쓰기 3택 템플릿 → 글 상세(투표 전/후·무난함 판정) → 댓글·추천
3. **시드 데이터** — 6개 탭 어디를 눌러도 비지 않게. 무난함 판정글은 투표가 쌓인 상태로. (콜드스타트 방어 = 데모 생명줄)
4. **매거진** — 아티클 목록·상세 + 테스트
5. **컨설팅** — 고수 목록·프로필(**대표 답변 3개는 실제 comments 레코드 참조 필수**)·예약 신청·완료
6. **내정보** — 프로필·닉네임 변경·온도 바·내 활동·내 예약
7. 하트 배지·차감 (최하위)
